This was proved with the example that the video with 500 frames took 10 hours to propagate and produce the masklet, with about 60 to 70 seconds per iteration/frame, and the subsquent runs took less than 1 hour with 3 to 4 seconds per iteration/frame. The video before with 6 seconds was similiar, initially took about 20 seconds per iteration, and the subsquent runs about 1 second per iteration. The faster ratio is likely due to the resolution and size of the images, the ones with multiphase having significantly higher resolution and size. The explanation for the subsquent runs being faster than the first ones are due to:
		- The first time you run a deep learning model like SAM-2, PyTorch and CUDA may need to compile and optimize the GPU kernels.
		- This can take a long time (hours in some cases), especially if it’s the first time you're running it on your GPU.
		- Once compiled, these optimized kernels are cached, making future runs significantly faster.

	- SAM2 expects 1 image (png) and 1 respective mask image (png) with the same name. But by exporting with Brush Labels to PNG it provides each annotation of individual bubble in each png file, and also does not refer to the name of the source image, only the id of the task. In other hand JSON file associates the ID of the task with the image name, which has a pattern were the name of the image in label studio ends with the real image name, for example, for "49df7abe-00001.jpg" the name of the source image is "00001.jpg". It was also needed to merge all the masks respective of an image into a single png. So it was opted with the following solution:
		- Export as JSON;
		- Export as Brush Labels to PNG;
		- Developed a python script "convert.ipynb" which does the following:
			- Load the JSON export.
			- Parse each task to find the original image filename (e.g. 00001.jpg).
			- Group all mask PNGs (task-<id>*.png) for each image.
			- Merge those masks into a single mask (with label values preserved).
			- Save the merged mask using the original image name (e.g. 00001.png) into Annotations_merged/.

🔍 Observations
Early Epochs (0–3):

Rapid convergence.

Losses approach zero by Epoch 3, indicating memorization of the tiny dataset.

Very low Dice and IoU loss suggest near-perfect segmentation, likely overfitting.

Later Epochs (4–9):

Significant instability, with total loss peaking at 9.82 in Epoch 9.

Large fluctuations in dice, iou, and class losses, signaling potential overfitting and high sensitivity to specific samples.

🧠 Interpretation
With only 3 samples and a batch size of 1, the model quickly overfits.

The sharp spikes suggest the model's loss landscape is volatile — likely due to:

The small dataset's lack of variation.

High gradient variance due to batch size = 1.

No regularization or validation feedback to stabilize training.

Losses like Dice and IoU spiking are especially concerning for segmentation consistency.
